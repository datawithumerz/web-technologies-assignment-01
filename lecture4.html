HTML5, Semantic Elements and Forms

A page should describe its purpose clearly, both to readers and to the software that reads it. Semantic elements give sections meaning. Forms let visitors enter information in a structured way.

1. HTML5 and the meaning of a page

HTML5 includes elements for page structure, native audio and video, and form controls such as email, number and date inputs. These features help browsers understand content and offer suitable controls.

The viewport meta tag helps mobile browsers use the device width when laying out a page. Flexible CSS widths still matter: the tag alone cannot fix a page filled with oversized boxes.

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Related browser features include <canvas> for drawing with scripting, localStorage for browser storage that can persist across sessions, and sessionStorage for storage associated with a page session. Storage and canvas drawing require scripting to use; adding ordinary HTML elements alone does not implement them.

Block, inline, div and span

A block element normally begins on a new line. Paragraphs and <div> containers commonly behave this way. Inline elements, such as <span> and <strong>, flow within a line of text.

<div class="note">
    <p>Learn <span class="topic">HTML</span> one example at a time.</p>
</div>

<div> groups a larger area without giving it a special meaning. <span> groups part of a line. Classes let CSS target those groups. CSS can change display behaviour, but the element's HTML content rules still apply. For example, a paragraph cannot contain another paragraph.

2. Choose elements that describe their job

A semantic element tells you what its content represents. Reading <nav> suggests navigation, while reading a generic <div> gives no such clue.

Common semantic elements
ElementPurpose
<header>Introductory content for a page or section.
<nav>A major group of navigation links.
<main>The page's dominant content.
<section>A related group of content, usually with a heading.
<article>A self-contained item, such as an article or news story.
<aside>Related supporting content, such as a side note.
<footer>Closing information about a page or section.
<header>
    <h1>Student Learning Guide</h1>
</header>
<nav>
    <a href="index.html">Home</a>
    <a href="lecture3.html">HTML</a>
</nav>
<main>
    <section>
        <h2>Getting started</h2>
        <p>Begin with a clear document structure.</p>
    </section>
</main>
<footer>
    <p>Keep practising with small examples.</p>
</footer>

The tags organise meaning. CSS is still responsible for their colours, borders and spacing. Good semantics help people using assistive technology, help software interpret a page, and make the source easier to maintain.

3. How a form sends information

<form> groups controls for collecting input. Its action identifies the receiving URL, and its method defines how the browser submits the data.

<form action="/register" method="post">
    <label for="student-name">Name</label>
    <input type="text" id="student-name" name="student_name" required>
    <button type="submit">Register</button>
</form>

The example needs a server endpoint at /register to process a registration. HTML creates the controls, but it does not supply that server behaviour.

  • GET: puts submitted values into the URL query. It is commonly used for retrieving information, such as a search.
  • POST: puts submitted values in the request body. It is commonly used when submitting information for processing.

POST does not encrypt data. HTTPS protects communication in transit. A password input hides characters on screen, but that also does not encrypt a submission.

Understand the attributes

id and for
An input's unique id matches a label's for. Clicking the label then focuses or activates its control.
name
Identifies the submitted field. The server receives named values such as student_name=Ali. An id alone does not give a field a submission name.
value
Can supply an initial text value or identify an option, such as the value of a radio button.
placeholder
Shows a short example before the visitor types. It is a hint, so it should not replace the visible label.

4. Choose a control for the information

Common input types
TypeUse
textA short line of text, such as a name.
emailAn email address, with basic browser format checking.
passwordText whose characters are visually masked.
numberA numeric value, such as marks.
dateA date, often with a browser date picker.
checkboxAn independent on/off choice. Multiple boxes can be selected.
radioOne choice from a group whose controls share a name.
fileSelecting a local file for a suitable upload form.

<select> provides a dropdown whose choices use <option>. <textarea> provides several lines of input. Write its initial text between its opening and closing tags. A <button> can submit or reset a form, depending on its type.

<label for="topic">Topic</label>
<select id="topic" name="topic">
    <option value="html">HTML</option>
    <option value="css">CSS</option>
</select>

<label for="message">Question</label>
<textarea id="message" name="message" rows="3"></textarea>

Group related choices

<fieldset> groups controls. <legend> names the group. Giving radio buttons the same name means only one of them can be selected at a time. Their values distinguish the choices.

<fieldset>
    <legend>Preferred topic</legend>
    <label><input type="radio" name="topic" value="html"> HTML</label>
    <label><input type="radio" name="topic" value="css"> CSS</label>
</fieldset>

5. Let the browser check simple rules

HTML can catch common input mistakes before a form is submitted. required prevents a field from being empty. min and max limit a number or date. pattern checks a text value against a format.

<label for="practice-reg">Registration number</label>
<input type="text" id="practice-reg" name="reg"
       placeholder="FA24-BSE-084"
       pattern="FA[0-9]{2}-BSE-[0-9]{3}" required>

<label for="practice-marks">Marks, from 0 to 100</label>
<input type="number" id="practice-marks" name="marks"
       min="0" max="100" required>

The pattern means the letters FA, two digits, -BSE-, then three digits. This example accepts FA24-BSE-084, but rejects FA24-BSE-84. It illustrates one format, rather than every possible registration number.

Try the form

Use sample values. Leave a required field empty or enter marks above 100, then press Check and continue. The browser should ask you to correct it. When the values satisfy the rules, the form opens a short explanation page.

Have you tried the examples?

This demonstration uses method="get", so named values appear in the destination URL. It does not create an account or save a record in a database. In a real application, the server must validate submitted values again because browser checks can be bypassed.

6. Make the page easier for everyone to use

  • Connect each form label to its control and show the expected format in visible text.
  • Use headings in a sensible order and semantic elements for page regions.
  • Give informative images useful alternative text.
  • Keep keyboard focus visible so people can see which link or control is selected.
  • Use readable text colours and describe errors clearly.

These choices help people using keyboards or screen readers, and they usually make the page clearer for everyone else too.

Try it yourself

  1. Build a page with a header, navigation, main content and footer.
  2. Create a labelled email input using type="email" and required.
  3. Explain why radio buttons share a name but use different values.
  4. Try an invalid registration number and explain which part of the pattern it breaks.
